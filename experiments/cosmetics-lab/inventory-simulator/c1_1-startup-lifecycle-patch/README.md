# C1.1 — InventorySimulator startup lifecycle patch probe

**Hypothesis under test (single question):** the C1 startup crash is caused by
InventorySimulator calling `Utilities.GetPlayers()` too early during listen-server
`Load()`, which hits `Server.MaxPlayers → GetMaxClients` before engine global
variables are initialized.

**Verdict before probe:** C1 exact-upstream = startup FAIL (cs2.exe crashed during
startup, WER faulting module `coreclr.dll` 10.0.326.7603, exception `0x80131623`,
offset `0x2d21ee`, no dump retained). Isolation A (plugin dir removed, everything
else identical) = CS2 starts and runs normally → failure domain converged to
InventorySimulator. CSS log recorded the managed `NativeException: Global
Variables not initialized yet` in `InventorySimulator.Load()` on every launch.

## Upstream provenance

- Repository: `ianlucas/cs2-css-inventory-simulator`
- Tag: `3.3.0`, commit: `fade4449aaa6d5153261c855d0cc12d7dacfefdd` (MIT)
- Exact diff applied: `c1_1-startup-lifecycle.patch` (one line, see below)

```diff

         _lastUrl = ConVars.Url.Value;
-        OnFileChanged(null, ConVars.File.Value);
+        Inventories.Load(ConVars.File.Value);

```

The committed `c1_1-startup-lifecycle.patch` (generated by `git diff` against the
pinned commit) is the authoritative diff.

Why this and nothing else:

- `Load()` only needs the initial inventory file load; `Inventories.Load(file)`
  is exactly what `OnFileChanged` calls first, without the follow-up player
  enumeration. `CCSPlayerControllerState` already initializes each player's
  `Inventory` via `Inventories.Get(steamId)` on connect, so nothing else is lost.
- `OnFileChanged` itself is NOT modified: a runtime `invsim_file` change still
  runs the upstream refresh-online-players logic.
- No gamedata / native signature / econ / knife / glove / weapon logic touched.
- No retry, timer, fallback or lifecycle state machine added.
