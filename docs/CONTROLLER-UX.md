# Controller 产品与交互规格

> **类型：目标产品规格（canonical）**。定义下一阶段应实现的用户体验，不代表当前代码已经实现，更不代表真实 CS2 已验收。具体实现状态以代码、安装事务、运行日志和实机证据为准。
>
> **范围：** Windows 本地 / 离线 CS2 人机 Controller 的产品信息架构、页面空间职责、操作和状态合同。视觉样式、配色、字体由独立视觉规范负责；运行时 ownership 和安全限制仍以 [ARCHITECTURE.md](ARCHITECTURE.md) 为准。
>
> **设计来源：** 用户实际使用反馈；Whatnamed/AgentKit 的 `product-discovery`、`product-ia-interaction`、`product-ux-review` 与 `personal-ui-delivery`。旧 Controller 页面、历史截图、实验安装界面只是当前实现证据，不是新目标的 IA 权威。

## 1. 产品目标与边界

目标用户是本人：打开工具，配置本地人机和 CT/T 饰品，完成必要的安全准备，进入离线 CS2。正常使用**不需要**知道 `MetaMod`、`manifest`、`profile`、`adapter`、`install ID`、`preset pointer`、`fixture`、`hash` 等内部概念。

用户优先任务：
1. 设定地图、Bot 模式/强度/行为、双方战队和真人替代位置，准备或启动一场本地对局。
2. 编辑本人的 CT/T 枪械、刀、手套和音乐盒，保存整套饰品方案并安全应用。
3. 发生组件过期、安装异常或配置未生效时，获得明确的可执行下一步，而非默认阅读诊断信息。

保留的真实能力：固定来源职业战队与历史版本、自由组队与选手搜索、真人替代席位、独立 CT/T 饰品、方案导入导出、精确安装和恢复、诊断数据。既有 Bot/Human 独立 failure domain 不得破坏。

不做：线上匹配、社区服务器、比赛统计平台、公开联赛管理、完整 Bot AI fork、未经实机验证的动态难度滑块和快捷换刀。

## 2. 命名与内容设计规范（全产品约束）

### 2.1 稳定导航与区域名

**一级导航只保留两个四字名词性条目：`对局配置`、`饰品配置`。** 齿轮入口为 `系统设置`，属次级工具入口，不与日常导航并列；不额外造“首页 / 工作台”。

| 层级 | 唯一规范名称 | 职责和放置 |
| --- | --- | --- |
| 一级 | **对局配置** | 模式、地图、难度、Bot 行为、双方阵容、常用对局与准备状态 |
| 一级 | **饰品配置** | CT/T 枪械、刀具、手套、音乐盒及方案管理、保存和应用 |
| 次级入口 | **系统设置** | 组件检查、兼容、恢复与数据管理；通常无需进入 |
| 对局区域 | **基础设置** | 地图、模式、难度、Aim、Nades、阵营与人数 |
| 对局区域 | **双方阵容** | 我方/对方、战队版本、五个席位及替换操作 |
| 对局区域 | **对局方案** | 保存、复制、重命名、选择和删除的常用配置 |
| 对局区域 | **准备状态** | 本次配置能否准备、实际安装与下局接收状态 |
| 饰品区域 | **饰品方案** | 当前方案、复制、切换、导入、导出 |
| 饰品区域 | **装备类别** | 枪械、刀具、手套、音乐盒 |
| 饰品区域 | **装备列表** | 所选阵营与类别下的可配置物品 |
| 饰品区域 | **外观列表** | 皮肤/外观搜索与选择 |
| 饰品区域 | **参数设置** | 磨损、模板、启用开关等当前物品字段 |
| 设置分区 | **组件状态** | 当前组件、版本、是否具备运行条件 |
| 设置分区 | **兼容检查** | 更新/文件身份检查及面向用户的恢复操作 |
| 设置分区 | **备份恢复** | 可用的精确恢复、操作历史和用户备份 |
| 设置分区 | **数据管理** | 方案导入/导出及本地数据 |
| 设置分区 | **诊断信息** | 日志、完整原因、来源、install ID 和哈希 |

这些名称一处定义、多处复用（导航、页面标题、面包屑、帮助、测试、AutomationProperties）。不得出现同一对象多个叫法，也不为了强行四字而使用不通顺的标题。不同层级可以有不同词长，但同一层级应遵循相同的语法和粒度。

**按钮统一“动词＋对象”**，例如 `保存方案`、`选择战队`、`替换选手`、`检查状态`、`应用饰品`、`检查组件`、`恢复配置`。不是所有按钮都必须四字；优先清楚、短、相同动作同名。不用“开一局”“我的饰品”“准备好，去游戏”“目标模式”“编辑器”“激活指针”“规则与应用”“阻断详情”作为正式页面/区域标题。

术语一对一：
- **对局方案**＝可复用的整局配置（含阵容、地图、模式、难度、人数、行为）。
- **饰品方案**＝可复用的 CT/T 整套饰品。
- **当前配置**＝自动保存的日常偏好；非法编辑保留在界面并显示未保存。
- **已保存**＝用户数据已落盘，绝不暗示已安装或游戏生效。
- **已写入**＝游戏关闭时受管 profile/模式文件已核验；Aim/Nades 与阵容等新地图读回。
- **已应用**＝相应运行时读回通过；涉及实际模型、投掷或战斗行为的真实性仍由实机验收确认。
- **需要处理**＝确有可确定的问题且有可执行操作；**无法确认**不得冒充正常或损坏。

错误提示按“发生了什么 → 直接影响 → 可做什么”，例如“困难已保存；关闭 CS2 并打开 Controller 完成文件应用后再启动游戏”。原始哈希、堆栈、版本依赖只能放诊断详情。成功不堆叠同义提示与卡片；每页不重复写功能副标题。

### 2.2 内容层次检查

页面标题说明所处对象，区域标题说明所做任务，表单标签标明字段，按钮表明动作，状态表达结果，帮助只在不符合直觉时出现。禁止把内部状态机名称直接展示给用户；不要给每个标题配一段同义说明，不要让未发生的错误占据首屏，不要在页尾重复同一组按钮。导航、区域、控件、状态与错误逐项做词汇表一致性验证。

## 3. 总体信息架构和共享布局

```text
Controller
├─ 对局配置
│  ├─ 基础设置
│  ├─ 双方阵容
│  ├─ 对局方案（内联选择／按需展开管理）
│  └─ 配置状态＋检查状态
├─ 饰品配置
│  ├─ 饰品方案（内联选择／按需展开管理）
│  ├─ 装备类别
│  ├─ 装备列表／外观列表／参数设置
│  └─ 保存与应用
└─ ⚙ 系统设置（次级）
   ├─ 组件状态
   ├─ 兼容检查
   ├─ 备份恢复
   ├─ 数据管理
   └─ 诊断信息
```

不要为“对局方案”“饰品方案”分别再建一级预设库；也不要将技术实现模块、安装器类型或插件名称作为导航依据。

共享 Shell：
- 左侧仅两项主导航，右上齿轮进入系统设置；点击设置后可返回原页面及原编辑位置。
- 顶部仅保留当前页面标题、当前方案（适用时）、一处简短总体状态；需要用户处理的事项就地提示，其他信息按需获取。
- 主体保留适合任务的信息密度：对局适合双阵容并排，饰品适合列表＋图集＋详情；不强迫页面共用相同列数或卡片。
- 主操作靠近任务结果且始终可达（固定操作栏），危险恢复不要和普通保存并列成等价主按钮。
- 1024×660（含窗口 chrome）、1280×840、125/150% DPI 均可操作；窄窗将双阵容转为上下或我方/对方 Tab，饰品浏览改成逐级列表/详情，不得隐藏主按钮、横向溢出或困住键盘焦点。
- 缺少图片/清单/网络时有实际可读的回退，加载态不得擦除已输入草稿。

## 4. 对局配置：完整页面合同

### 4.1 页面区域

```text
[对局配置]    [对局方案 ▾] [保存方案]                      [当前状态]
┌ 基础设置 ───────────────────────────────────────────────────────┐
│ 地图 [列表／最近]       模式 [普通人机 | 增强人机]               │
│ 难度 [简单 | 中等 | 困难]  瞄准 [混合 ▾]  道具 [正常 ▾]           │
│ 阵营 [CT | T]          我方 Bot [4 ▾]  对方 Bot [5 ▾]           │
└────────────────────────────────────────────────────────────────┘
[双方阵容]              [交换阵容]（与切换 CT/T 阵营严格分离）
┌ 我方 ────────────────────┐   ┌ 对方 ──────────────────────────┐
│ 战队 [FaZe ▾] 版本 [2024]│   │ 战队 [Spirit ▾] 版本 [2024]   │
│ 1. karrigan [替代我]     │   │ 1. chopper [替换选手]         │
│ 2. rain     [替换选手]   │   │ 2. magixx  [替换选手]         │
│ 3. ropz     [替换选手]   │   │ ...                            │
│ 4. frozen   [替换选手]   │   │ [恢复阵容] [保存阵容]          │
│ 5. broky    [替换选手]   │   └──────────────────────────────┘
│ [恢复阵容] [保存阵容]    │
└─────────────────────────┘
[配置状态：已保存／已写入／待关闭游戏应用／无法确认]
═════════════════════════════════════════════════════════════════
[重置配置]     [保存方案]      [检查状态]
```

“恢复阵容”只撤销当前阵容修改，不是恢复 CS2 文件；“交换阵容”交换两队内容但不暗改真人 CT/T 选择。主操作的最终名称由**真正能力**决定，不让“启动对局”与“准备对局”指向同一空操作。

### 4.2 基础设置控件

| 字段／动作 | 具体交互 | 完成／失败与重要边界 |
| --- | --- | --- |
| 地图 | 方案可保留地图，实际由用户在 CS2 内自由选图 | 地图选择不阻断日常配置，不要求方案地图与实际一致 |
| 模式 | `普通人机`、`增强人机`；单一选择源 | 选中不等于已安装；无需因为尚未安装就禁用选择 |
| 难度 | `简单`、`中等`、`困难`；与受管 Low/Medium/High profile 精确映射 | 已安装中等仍能选择困难；游戏关闭时自动核验并替换 profile，不恢复重装底座。暂不伪造实时滑块 |
| 瞄准 | `混合`、`头部`、`身体`；只在支持的模式真正应用 | 未装支持模块时提示限制；读回和真实行为分开判定 |
| 道具 | `关闭`、`较少`、`正常`、`较多`、`最多` | 当前地图无投掷线路时，不把“最多”显示为行为生效 |
| 阵营 | `CT` / `T`，表示真人计划加入的阵营 | 改阵营只重新映射双方，不清空队伍；局中不自动踢人或换边 |
| 我方 Bot／对方 Bot | 我方 0–4、对方 0–5，默认 4＋5＋真人 | 不出场席位有标记，不得多刷 Bot；无人机模式仍有人类本身 |
| 交换阵容 | 显式交换双方五人阵容，并提供撤销 | 保留已设阵营与 Bot 数；不混淆“阵营切换”与“阵容互换” |
| 恢复默认 | 局部重置仅影响目标组；全局重置需确认 | 不删除已保存的对局方案和个人阵容 |

选项变化自动保存当前日常配置并更新预览；游戏关闭时尽快应用受管 profile/模式文件，游戏运行中只保存并提示待关闭后应用。Controller 打开时自动落实，无需准备按钮；若退出 Controller，应先关闭游戏并重新打开 Controller 完成应用再启动 CS2。

### 4.3 双方阵容与选手选择

阵容编辑与启用开关分离。默认关闭，正常随机 Bot；启用后在下一张适用的本地地图开局窗口应用一次。Aim/Nades 不受此开关影响；普通模式不加载增强 Bot 模块，对应设置报告未应用。

- 我方和对方均提供队伍选择（推荐知名队伍、搜索固定 40 队、自定义阵容）与**明确的历史版本**。内置快照只读；修改生成当前草稿副本。
- 每方持续展示五个席位：姓名、是否出场、当前选手身份是否明确。我方任一席位有 `替代我` 动作，真人只占一席；其他席位 `替换选手`。
- `替换选手` 在对应行打开搜索面板，可搜索职业选手昵称、persona ID，也可输入自定义姓名；结果清楚展示重名消歧与已停用状态。完成后返回原行；Esc 取消且焦点恢复。
- 选择不同队伍／版本时，若草稿已修改，提供 `保存阵容`／`放弃修改`／`取消`；切 CT/T、人数或主页面不得丢失队伍修改。
- 人数较小时，仅将部分席位设为不出场，不丢弃五席完整阵容。队伍身份与 Bot 独特行为不等同，不声称模拟职业战术。
- 重复 ID、昵称编码/长度、控制台非法字符、缺失 persona 都在该席位或确认区提示；符合条件时可以使用普通显示名降级，但不能默默误绑另一个身份。
- `保存阵容` 创建个人副本，`恢复阵容` 复位到所选版本；`随机阵容` 改动可撤销。自定义阵容的改名/复制/删除归各自阵容菜单。

### 4.4 对局方案与持久化

`对局方案` 包含地图、模式、难度、行为、阵营、人数、双方阵容和真人替代位置。页面内的方案选择器显示最近/收藏/全部；管理项为 `新建方案`、`保存方案`、`复制方案`、`重命名`、`删除方案`、`导入方案`、`导出方案`。删除不能影响当前已开始对局。

区分**当前日常配置 / 已保存方案 / 已写入文件 / 已安装组件 / 当前地图读回**五类身份；它们不应该分别成为五个用户必经的编辑器。切方案时未保存修改明确处理，保存成功只说明本地方案落盘。

### 4.5 配置状态与日常开图

日常页面无需“准备对局”，保存设置后用户正常启动离线 CS2 并在游戏内任选本地地图。页面区分：

| 当前事实 | 展示与动作 | 不能声称 |
| --- | --- | --- |
| 当前配置已持久化 | `配置已自动保存` | 文件已应用 |
| 游戏关闭且受管文件读回通过 | `已写入`；正常启动 CS2 并选图 | 游戏内行为已验证 |
| 运行中修改 profile/模式 | `待关闭游戏后应用`；提示先关闭游戏并打开 Controller | Controller 未运行也能自动切换 |
| 首次缺组件、版本不匹配或旧整合层 | 系统设置 `检查组件预览` / `安装/升级组件` | 日常每次需恢复重装 |
| 本地图独立 mode/epoch 读回 | 分别显示 Aim、Nades 接收结果 | 阵容或实际投掷自动成功 |
| 本地图人数/persona/名称读回 | 显示阵容接收结果 | 真实战斗效果完全验收 |
| 陈旧或不同 revision/进程报告 | `上次地图报告（不能确认当前地图）` | 本图已应用 |
| 某模块缺失/阵容失败 | 对应失败原因，其他独立模块继续 | 全部成功或全部损坏 |

首次迁移、升级、修复与精确恢复保留预览、用户确认和原事务保护，仅在系统设置操作。低频组件安装与普通/增强日常模式开关分离。

## 5. 饰品配置：完整页面合同

### 5.1 页面布局

```text
[饰品配置]     [饰品方案 ▾] [保存方案]       [CT | T]
[装备类别：枪械 | 刀具 | 手套 | 音乐盒]
┌ 装备列表 ──────────┐ ┌ 外观列表 ───────────────┐ ┌ 参数设置 ──────────┐
│ 已配置 / 常用 / 搜索 │ │ 外观图、名称、筛选        │ │ 已选外观、磨损、模板 │
│ 选择真实武器或刀型 │ │ 缺图仍可按名称选择        │ │ 启用、移除、重置      │
└────────────────────┘ └─────────────────────────┘ └─────────────────────┘
[配置状态：未保存修改 / 已保存 / 需要关闭游戏应用 / 已写入配置]
═════════════════════════════════════════════════════════════════
[放弃修改]                    [保存方案]         [保存并应用]
```

- CT/T 在页面顶端统一切换，切换时保留彼此草稿及所选类别；字段归真实武器 defIndex，不改普通武器 identity；默认显示最近使用的阵营。
- 类别只显示相关控制：枪械和刀具可浏览外观；手套支持阵营启用/关闭与实际可用外观；音乐盒按本机 catalog 选择。不得将所有下级设置同时铺满首屏。
- 装备列表优先“已配置／常用”，支持搜索与清空；外观列表显示具体真实来源名称，长名称可阅读全文，图片缺失不影响选中。
- 参数设置直接反映本次选中的合法字段；磨损和模板输入校验在输入附近，切换型号不意外保存另一件物品。
- 选择外观属于编辑草稿，无需每选一次都弹确认。切页面/换阵营/关闭界面时，对未保存修改采取统一保护与恢复策略。

### 5.2 饰品方案与操作

`饰品方案` 永远是一套包含 CT 和 T 的完整配置；提供 `新建方案`、`保存方案`、`复制方案`、`重命名`、`删除方案`、`导入方案`、`导出方案`。方案切换不直接改真实 CS2 文件；除非用户点击 `保存并应用` 或明确 `应用饰品`。

| 操作 | 确定结果 | 失败 / 取消 |
| --- | --- | --- |
| 保存方案 | 本地方案持久化，留在当前编辑位置 | 保存失败保留草稿和原文件 |
| 保存并应用 | 保存完整 CT/T 方案；在安全条件下更新真实游戏配置并验证写入 | CS2 运行或组件不兼容时给可执行下一步，不显示“已应用” |
| 放弃修改 | 恢复至本次选中方案的上次保存值 | 对未保存变化进行有意义确认，不删除整套方案 |
| 切换方案 | 将目标完整 CT/T 数据载入可编辑草稿 | 原草稿未保存时提供保存／放弃／取消 |
| 导入方案 | 验证版本/冲突，不覆盖私人数据或无提示改名 | 保留原输入并说明错误 |

后台仍可保留工作草稿、激活记录、文件投影这些工程事实，但**不得要求用户理解或主动串联三个动作**才换一次饰品。正常情况用户执行一项 `保存并应用`；现有 Bot 活动事务不得成为永久不能应用 Human 的理由。解决方案必须兼容精确恢复和用户配置所有权；找不到安全实现不得通过取消哈希校验冒充成功。

## 6. 系统设置：次级页面合同

齿轮入口，正常可用时不占据日常工作首屏。从异常消息中的 `检查组件` 可以直接进入相关分区，解决后返回原页面、阵营、方案和滚动位置。

- **组件状态**：普通/增强模式真实安装、实际强度、游戏是否运行、组件是否可用；区分用户意向和真实安装，提供正确下一步。
- **兼容检查**：游戏更新、签名、版本或文件变化的只读检测。用户先看到“需要更新组件 / 安装未完成 / 暂不可用”及可执行操作；完整技术原因折叠。
- **备份恢复**：列出可证明的精确恢复记录，执行前必须只读预检、显示影响范围与确认；中断后不能靠“恢复最近一次”猜目标。
- **数据管理**：对局方案、饰品方案分组导入导出；历史备份不可自动清理；缺少 catalog 的准备入口在相关页面优先就地给出。
- **诊断信息**：支持查看或复制详细日志与 ID/hash，不在一级导航或正常状态卡片中长篇显示。

危险操作唯一序列：检查现状 → 核实将修改的实际文件 → 用户确认 → 有限操作及持久记录 → 校验结果 → 恢复入口。不得因交互简化而绕过真实保护；操作中断不能擅自重试未知的写入阶段。

## 7. 全局状态、导航与反馈

| 状态对象 | 必须保留的真实身份 | 用户可见表述 |
| --- | --- | --- |
| 对局草稿 | 当前选项及修改标志 | `未保存修改` |
| 对局方案 | 保存 ID / 更新时间 | `方案已保存` |
| 当前日常配置 | revision / 保存时间 / 阵容开关 | `配置已保存` / `待应用` |
| Bot 实际安装 | install record / manifest / profile / game build | `增强人机 · 中等难度` 或 `需要准备` |
| 游戏会话 | 进程启动身份、地图 session、revision 与新鲜度 | `本局配置已应用` / `无法确认是否应用` |
| 饰品草稿 | 方案 ID、CT/T 数据及是否变更 | `未保存修改` |
| 饰品游戏配置 | 实际写入和读回的映像 / 文件哈希 | `饰品已应用到配置`，不等于本局视觉验收 |

导航返回保留对象选择、筛选、搜索文本、当前编辑、滚动；按需清除过期的“已成功”状态而不是清空草稿。区分选择行、展开详情、执行命令；按钮忙碌、禁用和失败反馈明确，重复点击幂等。全局 Esc 关闭弹层后焦点回到触发控件。

游戏正在运行时仍可编辑未来对局与饰品草稿，但文件安装/恢复禁用；如果真实热应用能力未证实，不显示“立即生效”。Steam 在线启动不受更改；本地 `-insecure` 与地图加载只允许经过核实的有界操作，不能留在永久启动选项。

## 8. 按真实用户任务的验收合同

1. **日常对局**：打开 `对局配置`，选择增强人机、难度与 Aim/Nades，保持阵容关闭；文件写入完成后自行启动 CS2 并任选本地地图。另一次启用历史/自定义阵容，核对人数、名称/persona、TAB、计分与换边；两条路径都无须每局准备。
2. **更换难度**：已装 Medium 时选择 Low 或 High 不灰掉；游戏关闭后自动完成受管 VPK 替换和校验，安装 ID 与 Bot/Human DLL 不变；显示实际文件强度；如果被 Steam 更新或签名阻断，保留草稿和安装恢复现场，说明可做什么。
3. **更换饰品**：增强 Bot 活动时，在 `饰品配置` 编辑 CT/T 一套外观，`保存并应用` 安全写入并读回；CS2 实机显示正确，Bot 仍可用，精确恢复仍有效；无需先手工恢复普通 Bot。
4. **复用方案**：保存、复制、改名、导入/导出并重启，仍可复用本人的对局和 CT/T 饰品；不出现“激活指针”作为必经步骤。
5. **失败与恢复**：无数据、重名选手、阵容版本缺失、地图无道具线路、旧适配层、游戏运行、游戏版本漂移、恢复中断、图片缺失、缓存离线、无可靠游戏启动路径时均能给真实反馈；无假成功。
6. **窗口与操作**：1024×660、1280×840、150% DPI 与键盘均可完成主要操作；搜索清空、长名字、空数据、Escape、切页未保存保护完整；日常页面不堆技术字段。
7. **安全与验证分级**：构建/单测、WPF 离屏交互、隔离安装往返、正式本机安装、真人游戏确认分别记录。未经授权不得真实 Restore/Install 或启动 CS2，未真人验收的功能标记 pending。Aim/Nades 行为、Human 呈现与逐局 FPS 不能因读回记录即报 Accepted。

## 9. 设计自审与禁止回退

本版已确定：两个一级页面、一个次级设置入口；同级名称统一为规范名词短语；方案内聚到对应任务；安装切换由真实状态驱动；内部字段隐藏在诊断信息；视觉样式不在此决定。

不得退回五页技术模块导航；不得用“改文案 + 控件启用”冒充功能生效；不得将文件写入伪装成实际游戏行为；不得因为仪表盘方便制作就新增假 KPI、状态卡片或同义副标题；不得为了独立“饰品预设库”而让用户理解工作草稿/激活指针/投影差异。

实现须依照本目标规格，同时参照 [PRODUCT-SCOPE.md](PRODUCT-SCOPE.md) 和 [ARCHITECTURE.md](ARCHITECTURE.md)；若现有引擎机制不能满足某一条，先验证并给真实最短替代路径，保持用户数据和安全边界，不改变声明以假装已完成。
